# SPRAM v2 — Penjelasan, Verifikasi, dan Tindak Lanjut

Dokumen ini mencatat lapisan **di luar model**: kamus bahasa Indonesia, penjelasan
faktor, sistem pakar, konsultasi terpandu, dan tindak lanjut. Model, dataset, dan
training **tidak berubah** (tetap 36 fitur).

## 1. Pemisahan tanggung jawab

| Lapisan | Sumber | Mengubah model? |
|---|---|---|
| Prediksi + peluang | Random Forest (Main Model) | — |
| Penjelasan faktor | SHAP lokal, dihitung saat detail dibuka, memakai `model_version` snapshot tersebut | Tidak |
| Hipotesis + pertanyaan | Basis aturan (`rules`) dari 36 fitur + arah faktor | Tidak |
| Jawaban dosen | `consultations` | Tidak (hanya memperkaya tindakan) |
| Status penanganan | `cases` + `case_events` | Tidak (risiko tidak pernah berubah) |

## 2. Alur kerja

```
Admin ──assign──► Dosen wali
                     │
                     ├─ Ringkasan: risiko tinggi belum ditangani (prioritas) / sedang dipantau
                     ├─ Daftar Mahasiswa: filter risiko + filter penanganan (dua badge terpisah)
                     └─ Detail Mahasiswa
                          ├─ ringkasan risiko (model) + badge penanganan (manusia)
                          ├─ faktor: menaikkan / menurunkan risiko + latar belakang
                          ├─ profil 36 fitur berbahasa Indonesia
                          ├─ konsultasi terpandu (Ya / Tidak / Belum tahu)
                          ├─ tindak lanjut (status + catatan + linimasa)
                          └─ riwayat prediksi
```

Forward chaining: fakta awal = nilai 36 fitur + arah faktor SHAP → aturan dievaluasi
berurutan menurut prioritas → aturan yang cocok mengajukan pertanyaan → jawaban
menambah fakta → rekomendasi tindakan disusun → sesi disimpan.

## 3. Struktur data tambahan

| Tabel | Fungsi |
|---|---|
| `assignments` (student_advisor) | Pemetaan mahasiswa → dosen wali; dasar filter akses |
| `rules` | Basis pengetahuan: kondisi JSON, hipotesis, pertanyaan, tindakan per jawaban, prioritas, aktif |
| `consultations` | Jejak sesi konsultasi: jawaban + aturan aktif |
| `cases` | Status penanganan per mahasiswa (terpisah dari risiko) |
| `case_events` | Linimasa perubahan status |

Data training dan tabel `predictions` tidak diubah strukturnya.

## 4. Aturan awal

| ID | Sinyal (36 fitur) | Hipotesis | Tindakan utama |
|---|---|---|---|
| R01 | `Debtor = 1` atau `Tuition fees up to date = 0` | Kendala finansial | Rujuk keuangan, info keringanan/beasiswa |
| R02 | rasio `approved/enrolled` ≤ P25 (sem 1 atau 2), atau nilai sem 2 turun ≤ P25 | Kesulitan akademik | Bimbingan akademik, tutor sebaya |
| R03 | `Daytime/evening attendance = 0` dan `Age at enrollment` ≥ P75 | Bekerja sambil kuliah | Diskusi beban studi |
| R04 | `Application order` ≥ P90 | Kurang cocok dengan prodi | Konseling minat dan karier |
| R05 | `Displaced = 1` | Adaptasi & biaya hidup | Info tempat tinggal, komunitas |
| R06 | `Scholarship holder = 0` dan R01 aktif | Belum ada dukungan finansial | Info skema beasiswa |
| R07 | rasio `evaluations/enrolled` < 1 atau `without evaluations` ≥ 1 | Tidak mengikuti ujian | Hubungi segera, cek kehadiran |
| R08 | Risiko tinggi dan tidak ada aturan lain aktif (fallback) | Penyebab belum teridentifikasi | Percakapan terstruktur |

Ketentuan yang ditegakkan kode (`backend/expert.py: validasi_rule`):

- fitur **sensitif** (gender, kewarganegaraan, status keluarga, pendidikan/pekerjaan
  orang tua, kebutuhan khusus, internasional, status pernikahan) ditolak sebagai kondisi;
- fitur **makro** (pengangguran, inflasi, PDB) ditolak sebagai kondisi;
- nama fitur di luar 36 fitur model ditolak.

## 5. Ambang dari data latih

Diturunkan oleh `scripts/build_reference_data.py` dari `data.csv` (4.424 baris) dan
disimpan di `data/rule_thresholds.json` beserta cara penentuannya:

| Ambang | Nilai | Cara |
|---|---|---|
| `age_p75` | 25,0 | persentil 75 usia saat mendaftar |
| `application_order_p90` | 4,0 | persentil 90 urutan pilihan |
| `approval_ratio_p25` | 0,4286 | persentil 25 rasio unit lulus/unit diambil |
| `evaluation_ratio_p25` | 1,0 | dipakai dengan batas atas 0,99 agar tidak menjangkau seluruh populasi |
| `without_evaluations_p75` | 0,0 | dipakai dengan ambang minimal 1 unit |
| `grade_drop_p25` | −0,6 | persentil 25 selisih nilai semester 2 − semester 1 |

## 6. Kamus bahasa Indonesia

- `backend/dictionary.json` (dibangun oleh `scripts/build_dictionary.py`) memuat label
  36 fitur, kelompok, jenis faktor, arti nilai kode (dari tabel resmi dataset), kalimat
  penjelasan naik/turun, dan istilah antarmuka.
- `backend/dictionary.py` adalah penerjemah tunggal: `label()`, `terjemahkan()`,
  `kalimat()`, `profil()`. Kode yang tidak terdaftar tampil sebagai
  `Kode X (belum terdaftar)`, tidak pernah menyebabkan error.
- Konteks persentil ("lebih rendah dari 78% mahasiswa lain") dihitung dari distribusi
  data latih (`data/train_distribution.json`), tanpa menambah fitur.
- Pemeriksa: `.venv/bin/python scripts/check_dictionary.py`.

## 7. Contoh penelusuran satu kasus

Mahasiswa STD-0001, snapshot 2026-02-01, risiko tinggi.

1. Faktor teratas: `Curricular units 2nd sem (approved)` 0 dari 6, `Debtor = 1`,
   `Tuition fees up to date = 0`.
2. Aturan aktif: R01 (tunggakan + biaya belum lunas) → R02 (rasio lulus 0,17 ≤ 0,43)
   → R03, R04, R05, R06, R07 sesuai nilai fitur. R08 tidak aktif karena ada aturan lain.
3. Dosen menjawab R01 = "Ya" → tindakan: rujuk keuangan, info keringanan/beasiswa.
4. Sesi disimpan (`consultations`), status penanganan diubah ke "Dipantau" (`cases`).
5. Ringkasan menampilkan mahasiswa pada daftar "risiko tinggi, sedang dipantau";
   nilai risiko tetap tinggi.
6. Snapshot baru (2026-08-01) masih risiko tinggi → kasus dibuka kembali ke
   "Belum ditangani" dengan catatan otomatis "Dibuka kembali: prediksi terbaru tanggal …".

## 8. Batasan

1. SHAP bukan sebab-akibat; faktor adalah sinyal yang membuat model curiga.
2. Model hanya melihat 36 fitur; alasan nyata (kesehatan, keluarga, motivasi) tidak tercakup.
3. Data berasal dari Instituto Politécnico de Portalegre (Portugal); validitas untuk
   mahasiswa Indonesia belum dibuktikan.
4. Aturan disusun penulis dari fitur dataset dan logika domain, belum divalidasi pakar formal.
5. Jawaban verifikasi tidak mengubah prediksi model.
6. Keputusan akhir ada pada dosen (human-in-the-loop).
7. Penerjemahan mengikuti dokumentasi resmi dataset; arti sebagian variabel bisa berbeda
   dari istilah akademik Indonesia.
8. Sistem mengukur cakupan penanganan, bukan efektivitas pencegahan dropout.

## 10. Skenario demo (5–7 menit)

1. Admin membuka **Mahasiswa**, memilih beberapa mahasiswa, menetapkan dosen wali.
2. Masuk sebagai dosen → **Ringkasan** menampilkan "Risiko tinggi, belum ditangani".
3. Buka detail mahasiswa berisiko tinggi → baca ringkasan risiko dan faktor.
4. Gulir ke **Konsultasi terpandu** → jawab Ya/Tidak/Belum tahu → "Susun rekomendasi".
5. Tekan **Mengapa saran ini?** untuk menunjukkan aturan dan fakta pembentuknya.
6. **Simpan ke tindak lanjut**, ubah status ke "Dipantau" → tampil di Ringkasan bagian
   "sedang dipantau" sementara risiko tetap tinggi.
7. (Opsional) Jalankan prediksi snapshot berikutnya dengan hasil masih tinggi → kasus
   terbuka kembali otomatis.
